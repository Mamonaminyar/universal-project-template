# Contributing

## Before You Change Code

Read `README.md`, `docs/DEVELOPMENT.md`, `SECURITY.md`, and relevant issues or pull requests.

## Branches

Use short, descriptive branches:

```text
feature/<name>
fix/<name>
refactor/<name>
docs/<name>
chore/<name>
```

## Pull Requests

Every pull request should explain the problem, keep scope focused, include tests for behavioral changes, update affected documentation, and pass repository checks.

## Review Standard

Review correctness, security, maintainability, test coverage, operational impact and backwards compatibility.

## Commit Discipline

Prefer small, meaningful commits. Do not commit secrets or generated artifacts unless explicitly required.
